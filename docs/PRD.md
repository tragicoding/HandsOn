# PRD
## 개요
- 제품 이름 : Dutch-Pay
- 설명 : 모임 구성 원들의 다양한 변수로 인한 복잡한 정산 서비르를 제공한다. 
- 작성자 : 김진서
- 버전 : 1.0

## 배경과 문제
- 기존 카카오 정산하기 앱은 다양한 변수에 대한 적용할 수 없는 경우가 많다. 따라서 텍시, 음주하지 않은사람, 운전자 등등 다양한 변수를 적용하여 정산할 수 있는 서비스를 제공한다.
### 
    - 예시1 : 친구 A만 먼 지역에서 와서 교통비가 남들 보다 더 나오는데, 정산할 때 이를 반영하려 할 때
    - 예시2 : 8명이서 텍시를 4:4로 나누어 탑승하려 하는데, 각 텍시에 탑승한 사람마다 결제한 사람과 이후에 밥값 결제한 사람의 불일치에 따른 정산 복잡성
    - 예시3 : 술자리에서 친구A는 술을 아예 먹지 않아서 술값을 빼주기로 했다. 어떻게 해야 할까?
    - 예시4 : 친구 A는 운전자로서, 약 내야하는 금액의 20%를 감면해주고 N등분하여 정산해주기로 했다.
    - 예시5 : 모임에서 여러 명이 번갈아 결제하면 누가 누구에게 얼마를 보내야 하는지 계산하기 번거롭다.

## 목표와 성공 기준
목표

다양한 정산 조건 지원 : 단순 N분의 1 정산뿐만 아니라 개인별 지출, 정산 제외, 할인율, 차등 부담 등 다양한 조건을 적용할 수 있는 서비스를 제공한다.

복잡한 정산 과정 자동화 : 여러 구성원이 각각 결제한 내역과 정산 조건을 통합하여 구성원별 최종 부담 금액과 송금 금액을 자동으로 계산한다.

송금 과정 최적화 : 구성원 간 주고받아야 할 금액을 상계하여 불필요한 송금 횟수를 최소화한다.

직관적인 사용자 경험 제공 : 복잡한 계산 과정 없이 사용자가 지출 내역과 정산 조건을 간편하게 설정하고 결과를 확인할 수 있도록 한다.

투명한 정산 결과 제공 : 각 구성원의 부담 금액이 어떤 지출 내역과 정산 조건에 의해 계산되었는지 명확하게 확인할 수 있도록 한다.

성공 기준

정산 기능 완성도 : 배경과 문제에서 제시한 5가지 정산 시나리오를 모두 지원하며, 여러 조건을 동시에 적용할 수 있어야 한다.

정산 정확성 : 다양한 정산 조건에 대한 테스트 케이스에서 계산 정확도 100%를 달성하고, 총지출 금액과 구성원별 최종 부담 금액의 합계가 일치해야 한다.

정산 효율성 : 복합 정산 시나리오에서 수작업 대비 정산 소요 시간을 50% 이상 단축한다.

송금 횟수 감소 : 다수의 결제자가 존재하는 상황에서도 구성원 간 금액 상계를 통해 불필요한 송금 횟수를 줄인다.

사용 편의성 : 사용자 테스트에서 참여자의 80% 이상이 별도의 설명 없이 기본 정산 과정을 완료할 수 있어야 한다.

정산 신뢰성 : 모든 정산 결과에 대한 계산 근거를 제공하고, 지출 내역이나 조건이 변경될 경우 정확하게 재계산되어야 한다.

## 대상 사용자
- 모임에 참여하는 사람과 정산하는 사람
- 휴대폰으로 사용
## 범위
- 포함
    - 참여자 관리
    - 한 모임에 대한 여러 계산에 대한 관리(식사 -> 카페 -> 술집)
    - 자동 정산
    - 정산 결과(총 비용과 누가 누구에게 얼마씩 송금하면 되는지)
    - 결과 텍스트 복사
- 제외
    - 로그인
    - 서버 저장
    - 실제 송금

## 디자인
- 레퍼런스를 기반으로 하되, 색상이나 버튼 모양, 배치 등은 사용자 최적화 하게끔 한다. 
## 핵심 기능과 사용자 흐름
1. 참여자 입력
- 레퍼런스 : "docs\reference\web-01.png"
- 추가버튼 또는 Enter
- 레퍼런스 사진과 같이 이름 노드와 x표시로 삭제 가능하며, 삭제시 노드 색깔만 바뀜.
- 비활성화된 참여자의 경우 <지출 내역의 목록>에서 수정을 눌러 함께한 사람을 비활성화하여 사용한다. (참여자를 비활성화해도 이미 입력된 지출 내역은 자동으로 바뀌지 않는다.)
- 동명이인은 이름 뒤에 (1), (2)를 붙여 구분한다. (이미 있던 같은 이름은 (1)로 바뀌고, 새로 추가한 사람은 (2)가 된다. 이후 (3), (4)... 순서로 늘어난다.)
2. 지출 입력
- 레퍼런스 : "docs\reference\web-02.png"
- 항목
- 금액(원)
- 결제한 사람(토글)
    - 결제한 사람은 반드시 '함께한 사람'에 포함되어야 한다. (포함되지 않는 지출은 없다고 가정하며, 이런 입력은 예외처리로 거부하고 안내한다.)
- 전체 선택/해제
- 함께한 사람 (레퍼런스와 동일)
- 감면 인원 선택
    - 특정 인원 선택시 % 입력하여 해당 인원은 비용 감면
    - 감면율은 0~100의 정수만 허용한다. 소수(예: 12.5)는 예외처리로 거부하고 안내한다.
    - 감면 대상은 0명 이상 N-1명 이하까지만 가능하다. (전원 감면은 불가)
- 각 항목에 대한 결제 정보 목록 나열
- 만약 나누어 떨어지지 않을경우 -> 팝업창을 띄워 "결제자가 내기" or "랜덤" 버튼
    - 지출을 수정해서 저장할 때, 그 지출에 이미 선택해 둔 잔여 처리 방식이 있으면 팝업을 다시 띄우지 않고 기존 선택을 유지한다. (수정으로 처음 나누어떨어지지 않게 된 경우에만 팝업을 띄운다.)

3. 자동 정산 
- 레퍼런스 : "docs\reference\web-03.png"
- 정산 결과
- 레퍼런스와 같이 차액은 적절한 색으로 표시
- 레퍼런스와 동일하게 송금 목록 표시
- 결과 텍스트 복사 시 "docs\reflection\screenshots\p0-03-kakaotext-01.png" 참고
