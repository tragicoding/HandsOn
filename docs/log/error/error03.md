# error03 : 변경 규칙 4건이 phase2-doc에 반영되지 않음

- 오류 발생 날짜·시각: 2026-10-12 00:12 (KST)
- 발견 경로: `node scripts/test/run_tests.js` (test05)
- 해결 상태: 미해결 (이번 요청 범위는 test 적용까지이며 phase2-doc의 src는 수정하지 않음)

## 오류 메시지
```
FAIL 감면율 소수(12.5, 0.5, "7.5")는 거부되고 안내한다 (정수만 허용)
     └ 감면율 12.5가 통과됨 예상=false 실제=true
FAIL 감면율 범위 밖(-1, 101)과 숫자가 아닌 값("x")은 거부된다
     └ 감면율 -1가 통과됨 예상=false 실제=true
FAIL 소수 감면율이 든 지출은 계산에서 제외되고 사유가 남는다(다른 지출에 영향 없음)
     └  예상=50000 실제=100000
FAIL 결제자가 함께한 사람에 없는 지출은 거부된다 (이런 지출은 없다고 가정)
     └  예상=false 실제=true
FAIL 결제자가 함께한 사람에 없는 지출은 계산에서도 제외되고 사유가 남는다
     └  예상=50000 실제=80000
FAIL 명세서에 감면율 정수 / 동명이인 (n) / 결제자 포함 / 수정 시 기존 잔여 선택 유지 규칙이 정의됨
     └ 감면율 정수 규칙 없음
FAIL 수정 시 잔여 선택 유지: 이미 선택한 방식(랜덤/결제자)은 팝업 없이 그대로
     └ 이미 랜덤을 골랐는데 수정 저장 때 팝업이 다시 뜸
FAIL 동명이인: 같은 이름은 (1),(2),(3)으로 구분되어 추가된다
     └ (1),(2) 구분 안 됨: 김진서
FAIL [예외처리 성공] 감면율 소수 입력(12.5)은 거부되고 정수만 남으며 안내한다
     └ 소수가 그대로 남음: 125
FAIL [예외처리 성공] 결제한 사람이 함께 쓴 사람에 없으면 지출이 거부되고 안내한다
     └ 결제자 안내 없음: '박민수'은(는) 이미 있어요
```

## 예상되는 원인
1. 감면율: `validate.js`가 감면율의 형식을 보지 않고, `settle.js`의 `toPct`가 반올림·보정만 한다. 화면(`app.js`)은 숫자가 아닌 글자를 지우기 때문에 `12.5`가 `125`(→100%)로 바뀌는 문제가 있다. (조용히 다른 값이 되는 것이 가장 위험)
2. 결제자 포함: `validateExpense`가 "결제자가 함께한 사람에 있는지"를 검사하지 않고, 결제자만 있고 참여자가 아닌 지출도 그대로 계산한다. (가정 처리)
3. 동명이인: 화면 쪽 이름 검사가 중복이면 거부만 하고 번호를 붙이지 않는다.
4. 수정 시 잔여: 수정 저장 때마다 팝업을 다시 띄운다. 이전에 고른 mode/seed를 물려주지 않는다.
5. 명세서: 이 브랜치의 PRD/requirements/test.md는 이번 규칙이 없다(test.md만 교체함). 

## 예상되는 해결방법
- phase2-claude에서 한 것과 같은 방식으로 수정하면 된다. (1) `validateExpense`에 결제자 포함·감면율 정수 검사 추가, (2) 감면율 입력칸에서 소수점 입력 시 안내하고 소수 부분 버리기, (3) 이름 검사를 (1),(2) 번호 방식으로 변경, (4) 수정 저장 시 이전 mode/seed 유지.
- 명세서(PRD·requirements)에도 같은 규칙을 먼저 반영한 뒤 코드를 고치고 재테스트한다. 수정 후 기존 테스트도 함께 다시 실행한다.
