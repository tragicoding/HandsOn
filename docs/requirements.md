## 비기능 요구 사항

1. 기본 정산: 각 지출 항목의 총금액을 정산 참여자 수(N)로 균등하게 나눈다.
2. 감면 적용: 감면 대상자는 기본 부담 금액에서 설정된 비율(K%)만큼 감면받으며, 감면된 금액은 나머지 N-1명에게 균등하게 재분배한다.
3. 잔여 금액 처리: 원 단위 정수 계산에서 발생하는 잔여 금액은 결제자가 부담하거나 정산 참여자에게 무작위로 배분한다.
4. 최종 정산: 모든 지출 항목의 개인별 부담 금액과 실제 결제 금액을 합산하여 차액을 계산하고, 구성원 간 송금 관계를 상계한다.
5. 정합성 검증: 모든 정산 결과에서 총지출 금액과 참여자별 최종 부담 금액의 합계는 일치해야 한다.
6. 나누어떨어지지 않는 정산 : 정산 금액이 나누어떨어지지 않을 경우, 몫을 균등하게 배분하고 나머지 금액을 1원씩 참여자에게 분배하는 방식
알고리즘은 다음과 같다.
```
FUNCTION CalculateExpense(total, participants, discount, mode):

    N = 참여자 수

    // 1. 기본 부담 금액 계산
    각 참여자의 부담액 = total / N

    // 2. 감면 적용 (감면 대상이 있는 경우)
    IF discount 존재:
        감면 대상 부담액 *= (1 - 감면율)
        감면 금액을 나머지 N-1명에게 균등 재분배

    // 3. 원 단위 정수 처리
    각 참여자의 부담액에서 소수점 이하 버림

    remainder = total - SUM(각 참여자의 부담액)

    // 4. 잔여 금액 분배
    IF mode == "결제자가 부담":
        결제자 부담액 += remainder

    ELSE IF mode == "랜덤 배분":
        참여자 순서를 무작위로 섞음

        FOR i = 0 TO remainder - 1:
            참여자[i] 부담액 += 1

    RETURN 각 참여자의 최종 부담 금액
```
7. 송금 횟수는 최대 "인원 − 1"번
8. 모든 사람의 차액 합은 항상 0
9. 금액은 원 단위 정수만 허용한다. 
10. 호환성: 최신 크롬, 사파리, 엣지에서 동작
11. 사용성: 모바일 화면(너비 360px 이상)에서 가로 스크롤 없이 사용
12. 데이터: 서버로 전송하지 않고 브라우저에만 저장
