# test.md

## instruction
- 소스코드는 `HandsOn/src`에 있다.
- `scripts\test`의 스크립트에 의해 테스트가 실행된다. 
    - 해당폴더가 비어있다면 생성한다.
## 정산 테스트 규칙

### 앱실행 테스트
- 정상적으로 앱이 열리는가
- PRD에 따라 모든 기능이 정상 작동하는가

### 정산 테스트 시나리오
- 참여자 수: 5명, 10명, 15명, 20명
- 지출 항목: 1개 및 여러 개(식사, 카페, 술집, 택시 등)
- 결제자: 단일 결제자 및 여러 결제자
- 정산 대상: 전체 참여 및 일부 참여
- 감면 조건: 감면 없음, 0%, 20%, 50%, 100%
- 잔여 금액: 나누어떨어지는 금액과 나누어떨어지지 않는 금액
- 잔여 처리: 결제자가 부담, 랜덤 배분
- 예외 상황: 참여자 비활성화(기존 지출 유지, 수정에서 해제), 전원 감면 거부, 금액 수정, 항목 삭제, 잘못된 입력
- 추가 예외 상황: 소수 감면율 거부(정수만 허용), 동명이인 (1)(2) 구분, 결제자가 함께한 사람에 없는 지출 거부, 지출 수정 저장 시 기존 잔여 처리 선택 유지



### 검증 기준
- 총지출 금액 = 모든 참여자의 최종 부담 금액 합계
- 모든 계산 결과는 원 단위 정수
- 감면 및 재분배 규칙 준수
- 감면 대상은 0명 이상 N-1명 이하까지만 가능하다. 전원 감면은 거부되어야 하고, N-1명 감면은 허용되어야 한다. (여러 명 감면 시 감면 대상이 아닌 사람에게 균등 재분배)
- 비활성화된 참여자의 경우 <지출 내역의 목록>에서 수정을 눌러 함께한 사람을 비활성화하여 사용한다. 참여자 비활성화만으로 기존 지출·정산 결과가 바뀌면 FAIL이다.
- 감면율은 0~100의 정수만 허용한다. 소수(12.5 등)는 거부(예외처리)되어야 하고 100%·0%는 정수이므로 허용된다.
- 동명이인은 이름에 (1),(2)... 번호가 붙어 구분되어야 한다. (기존 이름은 (1), 새로 추가한 사람은 (2), 그다음은 (3)). 이름이 겹쳐도 추가가 거부되면 FAIL이다.
- 결제한 사람이 '함께한 사람'에 없는 지출은 거부(예외처리)되어야 하며, 계산에서도 제외되고 사유가 남아야 한다.
- 지출 수정 저장 시 이미 잔여 처리 방식이 있으면 팝업 없이 기존 선택(결제자/랜덤, seed)이 유지되어야 한다. 수정으로 처음 나누어떨어지지 않게 된 경우에만 팝업이 떠야 한다.
- 참여자별 결제 금액과 부담 금액의 차액 정확성
- 최종 송금 금액의 채권·채무 관계 일치
- 동일한 입력과 저장된 랜덤 배분 결과에 대해 동일한 정산 결과 보장
- 테스트 결과를 PASS/FAIL로 기록하고 실패 원인 보고
- 예외처리로 지정한 것이 그대로 소스코드 의도대로 에러처리되었다면, 이는 PASS다. 

### 테스트 원칙
- 주요 조건을 조합한 다양한 테스트 케이스를 생성한다.
- 테스트 결과는 독립적으로 계산한 예상값과 비교한다.
- 수정된 기능과 관련된 기존 테스트도 다시 실행한다.
- 테스트를 실제로 실행하지 못한 경우 미실행으로 보고한다.

### 명세 미정의 동작과 가정 처리 (실패 판정 규칙)
- PRD·requirements에 정의되지 않은 동작을 AI가 "가정"하여 처리한 경우, 그 항목은 PASS가 아니라 **FAIL(오류)** 로 기록한다.
    - 예: 전원 감면, 비활성 참여자가 포함된 기존 지출, 여러 명 동시 감면처럼 명세서에 규칙이 없는데 코드가 임의로 처리하는 경우
- 가정으로 통과시킨 항목을 test log에서는 PASS, error log에서는 "가정 처리"로 따로 적어 서로 모순되게 두지 않는다. test log와 error log의 판정은 항상 같아야 한다.
- FAIL이 나오면 reviewer가 error log에 기록하고, implementer가 예외처리를 수정한 뒤 해당 테스트를 다시 실행한다. 수정 후에는 기존 테스트도 함께 다시 실행한다.
- 테스트 스크립트는 현재 `src`의 구조(함수·파일)에 맞게 유지한다. src 구조가 바뀌어 실행되지 않으면 "미실행"으로 넘기지 말고 스크립트를 재작성한다.
